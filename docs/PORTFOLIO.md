# 作品集讲解与学习练习

这个项目用于展示 Agent 应用开发过程：把模型输出转换为有权限边界、有状态记录、能检查实际产物的任务流程。界面、后端、运行时集成和测试应一起讲解。

## 三分钟项目讲解

> 我做的是中文 AI 陪伴与任务执行原型。用户可以聊天，也可以提出工作区文件任务。服务端负责持久化任务状态，真实模式连接固定版本的 DeepSeek Harness；工具涉及写入时先给用户展示具体操作，再执行获批的计划。结果用真实文件和校验信息证明。公开仓库提供不用密钥的离线演示，方便快速复现；真实模型、语音及多模态接口的验收分别记录。

以上是项目行为说明，不是已确认的个人贡献声明。面试时只认领自己实际理解、实现或复核的部分。

建议按以下顺序演示：

1. 说明当前模式与输出来源，展示聊天界面和任务卡。
2. 提交有界文件任务，解释任务 ID、状态与事件。
3. 展示具体写入计划，说明审批与模型决策的区别。
4. 下载实际产物，展示内容与路径；真实模式再核对工具事件及哈希。
5. 取消任务或补充要求，解释未执行计划与已完成操作各自如何处理。
6. 说明当前限制及下一项有明确验收标准的改进。

## 关键设计取舍

| 选择 | 原因 | 当前代价与后续问题 |
| --- | --- | --- |
| 固定 Harness 版本 | 便于复现协议与插件行为，排查兼容性问题 | 安装包含原生依赖；升级需要独立验证 |
| 本地监听与独立工作区 | 先把权限、文件任务与交互做清楚 | 公网部署仍需认证、隔离、配额与运维 |
| 确定性权限规则独立于 Jev | 决策候选不能自行授予执行权限 | 需要维护权限契约与拒绝行为 |
| 具体操作审批与文件哈希 | 批准内容与实际修改绑定；检测文件已变化 | 需要处理计划过期、用户补充与部分成功 |
| 任务事件与实际产物 | 让失败与结果可以审查 | 尚缺跨进程追踪与效果评测 |
| 离线演示与真实模式分开 | 新访客无密钥也能复现界面与流程 | 演示必须标明 mock，不能当作模型效果证明 |
| 重启后标记 interrupted | 保留事实，避免未经验证的重复操作 | 自动安全恢复尚未实现 |

## 可以证明什么

源代码与离线回归可以验证输入限制、权限拒绝、状态更新、审批、文件操作、取消和适配契约。使用 fixture 的测试只能证明约定行为，不证明真实模型质量。

[ACCEPTANCE.md](../ACCEPTANCE.md) 与固定版本记录保存了此前本机的 Harness 文件任务与文件语音回路结果。它们是历史验收信息，不能自动替代当前公开版本的复测。新的真实验收记录应注明日期、版本、模式、输入、实际产物、失败项与可公开证据；不保存私人对话、凭据或原始参考媒体。

后续评测应把三类结果分开：程序是否按契约执行、模型是否选对工具、用户任务是否真正解决。

## 每周 6–8 小时的实践路线

每周建议分配：概念学习 1–2 小时，实现 3–4 小时，测试与记录 1 小时，讲解和面试练习 30–60 分钟。下表是待完成的练习，不表示当前已有相应能力或功能。

| 周次 | 在这个仓库完成的练习 | 验收与作品集证据 |
| --- | --- | --- |
| 1 | 跑通离线演示，画出任务的接口与状态，独立修改一个交互或校验点 | 从干净 checkout 复现；提交改动并解释数据流 |
| 2 | 读懂模型请求、响应解析、超时与取消；用 fixture 复现失败 | 失败返回真实错误，日志不含密钥；说明请求与响应契约 |
| 3 | 在独立实验模块手写最小 Agent loop，练习工具调用与停止条件 | 测试最大轮次、无工具结果与未知工具；比较上游运行时和自己的实现 |
| 4 | 增加可管理的会话记录与记忆草稿 | 区分消息历史、任务状态、长期记忆；支持查看与清除 |
| 5 | 用公开样例材料做检索问答 | 引用可回到原文；材料不足时说明缺口；保留 10 个检索案例 |
| 6 | 设计 interrupted 任务的人工恢复流程 | 重启不重复写；用文件现状与事件决定是否重试 |
| 7 | 补审批与幂等边界 | 覆盖旧审批、哈希变化、部分成功、重复提交与取消竞争 |
| 8 | 把有界工具封装为 MCP 实验服务，解释与 tool calling、Skill 的区别 | 权限在调用端保留；用最小客户端调用并记录参数契约 |
| 9 | 建立至少 30 条固定任务评测与成本记录 | 分别统计任务成功、工具选择、权限拒绝、延迟与失败原因 |
| 10 | 做干净环境安装记录与三分钟演示 | README、版本说明、效果报告、个人贡献和限制一致 |

每次练习提交附四行说明：解决什么问题、改了哪里、如何验证、还有什么没完成。一个学习阶段可以拆成多个小提交，不需要一次重写整个项目。

## 面试追问练习

- 普通聊天、固定工作流和 Agent loop 的差别，在本项目分别在哪里？
- 模型生成工具参数后，为什么仍需要确定性权限检查？
- 工具已经写入文件，但模型连接随后失败，用户应该看到什么？
- 用户批准后文件又被其他程序修改，如何避免覆盖新内容？
- 取消后迟到的模型消息或产物，怎样避免重新发布？
- 会话历史、执行状态和长期记忆分别保存什么，为什么不能混为一谈？
- RAG 没找到材料与模型回答错误，怎样分别定位？
- 怎样从 mock 测试推进到真实接口验收，再推进到任务效果评测？

讲解时先用具体案例回答，再指出对应代码和测试。尚未实现的能力，应给出方案与验收条件。
